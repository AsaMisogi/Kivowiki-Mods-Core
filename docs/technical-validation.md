# Kivowiki-Mods 技术验证清单

本文用于发布前和站点适配器开发时的人工测试。它只验证管理器能力和模块契约，不包含任何具体站点接口、地址或业务调用方法。

## 基础安装

- 在干净浏览器配置中加载扩展，确认清单 JSON 可解析。
- 检查扩展只匹配目标 Wiki 页面，不会在其他站点注入。
- 在支持的 Chromium 版本中确认 User Scripts 能力状态可见。
- 刷新扩展后刷新页面，确认管理器入口只出现一次。

## 配置中心

- 首次打开配置中心，模块与依赖双列表、独立搜索、空状态和安全模式状态正确显示。
- 连续打开、关闭、重新打开同一模块配置，确认不会停留在加载状态。
- 配置页中的复选框、数字输入和键盘操作均可用。
- 快速切换两个模块配置，确认旧 iframe 的消息不会写入新模块。
- 连续保存设置，关闭窗口后重新打开，确认最后一次有效设置被保留。
- 配置脚本抛出异常、异步挂载失败或超时，确认界面显示错误并可关闭重试。
- 在 Edge 中打开 quick-tools 配置并修改任意设置，确认不出现 `Cannot read properties of undefined (reading 'catch')`，设置仍能保存。
- 点击内置快捷工具“配置”，确认能加载 `modules/Kivowiki-Mods-quick-tools/src/config.js`，不再显示 `Failed to fetch`。
- 在配置中心确认“已安装模块”列表显示 `Kivowiki-Mods-quick-tools`，并确认 `options.html` 与 `popup.html` 不再请求不存在的 `modules/quick-tools/src/index.js`。
- 在桌面和窄屏窗口检查健康概况、模块标识、折叠详情、安装确认、日志和历史版本弹窗没有重叠或溢出。
- 分别从 GitHub 与 GitLab 公开仓库导入模块和依赖，确认默认分支下载后进入相同预检；私有仓库、非 HTTPS 与非仓库链接应失败。

## 安装预检

- 分别导入无签名、自签名有效、签名异常和签名密钥变化的包；均应允许用户确认安装，并显示对应的轻量提示。
- 检查必需权限、可选权限、未知权限和用途说明。未知权限应保存但不授予；取消可选权限后，宿主 API 应拒绝该能力。
- 检查页面模式与严格沙箱的能力提示。严格沙箱声明页面或网络权限时允许安装，但运行时不得开放能力。
- 检查作者、来源和审核声明不会被误显示为官方认证；首次自签名与作者密钥延续应明确区分。
- 确认安装界面只需一次决定，不使用连续弹窗阻碍用户自主安装。

## 模块生命周期

- 启用、停用、重载模块，确认 DOM、事件监听器、定时器、观察器和样式都被清理。
- 在页面导航或路由变化后验证模块不会重复挂载。
- 修改设置时优先触发 `onSettingsChange`，不应重复创建整棵 UI。
- 页面模式和严格沙箱模式分别测试；沙箱模式不能访问页面 DOM、扩展 API 或网络。
- 恶意或损坏的资源路径、重复文件、非法入口和缺失清单应被拒绝。
- 同时启用大量模块，确认按依赖顺序且每批最多 4 个启动；单个模块失败不影响其余模块。
- 制造 5 分钟内 3 次启动失败，确认默认自动隔离；重新启用后清除隔离记录。
- 模块消息超过每秒 60 条时确认额外消息被丢弃且日志只提示一次限频事件。

## 数据能力

- 使用无效 URL、写入方法、非法协议、缺失参数测试参数校验。
- 使用慢响应、网络断开、408、429 和 5xx 验证超时与有限退避。
- 验证 4xx 不会无限重试，业务失败信封会被拒绝。
- 验证缓存 TTL、缓存容量上限和 `clearCache()` 行为。
- 验证数组查询参数按重复参数编码，未知字段不会导致解析崩溃。
- 验证请求头中的认证信息不会被模块能力自动转发。
- 批量任务验证并发限制、取消路径、分页终止和失败记录。

## 包与备份

- 用 ZIP 根目录和单层项目目录分别导入，确认能识别 `module.json`、`dependency.json` 和 `manifest.json`。
- 测试 Store/Deflate 压缩、重复文件、路径穿越、加密包、损坏 CRC 和超大文件。
- 导出单模块和全部社区模块，重新导入后检查入口、配置、资源、设置和启用状态。
- 移除模块后确认 IndexedDB 资源已清理，其他模块不受影响。
- 导入同 ID 的升级、降级和重装包，确认旧版本自动进入历史，最多保留 3 份。
- 回滚到任一历史版本，确认当前版本被保留、设置和启用状态不丢失。
- 构造缺失依赖、版本不符、循环依赖和双向冲突，确认允许安装但相关模块暂不运行。
- 构造两级以上传递依赖，确认依赖按拓扑顺序初始化且每个页面每个版本只有一个实例；升级依赖后相关模块应重启。
- 同时安装同一依赖的两个主版本，确认不同模块按版本范围选择各自版本，资源以 `ID@版本` 独立保存且互不覆盖。
- 导出锁文件，确认记录模块摘要、来源和实际依赖版本；安装新依赖版本前后分别验证锁定复用与用户主动升级。
- 为模块填写 `dependencySources`，确认缺失依赖会自动下载并逐个进入审核，不会静默安装或覆盖内置包。
- 构造依赖对依赖、依赖对模块的单向 `conflicts`，确认相关依赖卡片和所有使用模块都显示阻止原因。
- 构造错误的 `exports` 接口和重复的 `claims`，确认前者阻止受影响模块，后者只显示资源占用提示。
- 尝试跨模块/依赖类型使用同一 ID、缺少 `Kivowiki-Mods-` 名称前缀或从错误入口导入包，确认均被拒绝。
- 确认导出的备份不沿用作者原始签名，重新导入时显示未签名而不是错误的认证状态。

## 性能与安全

- 使用 Performance 面板观察页面长任务、重复渲染和频繁消息。
- 约束用户输入和远程内容使用 `textContent` 或经过过滤的渲染器。
- 检查 CSS 使用模块前缀，不覆盖无关页面节点。
- 检查模块日志不包含 Cookie、Token、账号信息或完整敏感请求头。
- 检查日志只保留最近 500 条，每模块每分钟最多接受 100 条，并可按级别筛选和清空。
- 多个 Wiki 标签页同时保存不同模块设置，确认只更新目标模块，不覆盖其他模块的新状态。
- 修改设置时确认后台不会无条件重新注册全部 User Scripts；升级、权限、依赖或启停变化时才同步注册。
- 发布包中不包含内部测试资料、未审阅模块、凭据或独立站点适配资料。

## quick-tools 回归

- 默认状态下角色图鉴按钮固定显示在返回顶部按钮上方；点击后应优先触发顶部菜单内部的 `.n-a` 文字链接。若顶部入口尚未渲染或未响应，再兼容侧边栏或主页“拿起角色图鉴”入口，出现 KivoWiki 原生图鉴窗口和“搜索角色”输入框。
- 点击图鉴按钮时模块不得创建自己的图鉴面板，也不得自行请求 `/api/v1/data/students`；筛选、分页和资料跳转全部由站内功能负责。
- 夜间模式下检查 `/data/character/108`：只将黑色地形 PNG 转为浅色，不反转旁边彩色评级 WebP。
- 夜间模式下检查 `/contact`：标题、列表、引用、链接和按钮文本均具备足够对比度。
- 夜间模式切换后立即检查正文文字、Naive UI 图标和导航颜色，确认没有约 0.2 至 0.3 秒的颜色渐变延迟；按钮悬浮等后续交互动画仍可正常使用。
